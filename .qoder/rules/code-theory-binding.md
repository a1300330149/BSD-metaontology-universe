## 代码标注强制要求

每个 Python 文件头部必须包含以下注释：

```python
"""
归属基底：第X重XX基底
对应三界秩序：天道/自然/人道
对应公理：第X条（宿命双边界/科研动力学/价值边际等）
对应九维维度：元理天道/载体实体/因果社会...
理论原文出处：《V3.0元本体理论分册》第X章
核心数理参数：γ=0.92, κ=0.42(竞赛稀疏分支)
"""
```

## 禁止行为

1. 禁止使用通用 AutoML / 强化学习原生定义替代本体系本源公理
2. 禁止修改锁档参数、流转矩阵、边界约束
3. 禁止颠倒宇宙基底推导顺序（只能 0→1→2→3→4，不能反向）
4. 禁止生成与九维、三界、双边界冲突的算法逻辑
5. 禁止删减文档确权扉页、哈希存证段落
6. 禁止代码实现与 1 重九维法理、2 重三界秩序规则冲突

## 理论-代码双向绑定

### 标准开发顺序（自上而下，强制）

1. 先在 `theory_base/` 对应基底文档新增公理/公式/规则
2. 再按目录层级新建对应代码文件，头部填写理论映射注释
3. 运行验证脚本（`bsd-verify-hash` + `bsd-verify-axiom`）
4. 修复所有缺陷，双向同步完成

### 禁止反向流程

不允许先编写代码后补理论解释；此类代码天然存在割裂风险。

### 双向锚定强制

- 每个理论锚点必须有对应代码锚点
- 每个代码锚点必须有对应理论锚点
- 理论有内容无代码 → 标记为割裂缺陷
- 有代码无理论条目 → 标记为割裂缺陷

## 宇宙基底层级（0-4重）映射

| 层级 | 名称 | 工程映射 |
|:---:|:---|:---|
| 0重 | 元道本源基底 | 锁档公理层（只读引用） |
| 1重 | 九维法理基底 | `bsd_engine/core/`（全局状态、M7矩阵） |
| 2重 | 三界秩序基底 | `bsd_agents/`（四层智能体分层权责） |
| 3重 | 六阶自主科研业务 | `bsd_engine/`（FO/SO六阶流水线） |
| 4重 | 四层智能体执行载体 | `bsd_agents/`（底层实体/中层决策/顶层主控） |
